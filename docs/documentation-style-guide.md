# VeriMod 문서 작성 가이드

> **대상:** A·F·T 및 문서 검토자 · **목적:** 기술적 의미와 증거를 보존하면서 한국어 Markdown의 탐색성과 표기를 통일합니다.
>
> **기준:** 2026-10-31 문서 감사. 이 가이드는 프로토콜 규격·정책·승인 절차를 변경하지 않습니다.

## 문서 종류와 변경 원칙

| 종류 | 목적 | 변경 원칙 |
| --- | --- | --- |
| CURRENT / GUIDE | 현재 상태와 사용 경로 안내 | 코드·설정·검증된 근거와 대조하고 기준 SHA를 표시 |
| SPEC | 승인된 인터페이스·계산 규칙 설명 | 기술적 변경은 별도 승인과 리뷰가 필요 |
| DECISION | 승인자·상태·근거·경계 기록 | 과거 결정을 소급 변경하지 않고 이후 결정을 별도 연결 |
| EVIDENCE / HISTORY | 당시 실행과 판단 보존 | 원본 수치·날짜·해시를 유지하고 이후 상태는 별도 업데이트 |

## 권장 구조

1. 문서의 H1 제목 하나와 대상·목적.
2. 기준일, 기준 SHA, 작성자 또는 담당자, 상태.
3. 핵심 요약과 독자가 먼저 할 일.
4. 구조·절차·결과를 설명하는 H2/H3.
5. 근거 링크, 제한 사항, 미완료·다음 행동.

기록이 긴 문서는 먼저 3~5개의 핵심 항목과 탐색 링크를 제공합니다. 역사 문서의 기존 제목·앵커와 원문을 양식 때문에 일괄 변경하지 않습니다.

## 상태와 증거

| 상태 | 사용 기준 |
| --- | --- |
| `APPROVED` | 확인 가능한 승인 주체·대상·시점·범위를 기록. 구현 완료와 구분 |
| `PASS` | 실제 확인한 조건과 테스트·환경을 명시. 전체 서비스 보장 아님 |
| `PARTIAL` | 충족한 조건과 남은 조건을 함께 기술 |
| `NOT_VERIFIED` / `NOT_EXECUTED` | 근거 부족과 실행하지 않음을 구분 |
| `BLOCKED` | 구체적인 선행조건이나 접근 불가 사유를 표시 |

코드 존재, CI 성공, 실제 실행, 담당자 보고, 합성 테스트, 계획은 [증거 안내](evidence/README.md)의 구분을 사용합니다. `SKIP`을 PASS로 세지 않으며, 다른 날짜의 결과를 새 실행에 합산하지 않습니다.

## Markdown과 표현

- 한국어 문장을 기본으로 하되 API·상태·파일·프로토콜 식별자는 원문을 유지합니다.
- H2/H3로 계층을 구성하고 제목·표·목록 앞뒤에 빈 줄을 둡니다.
- 표에는 간단한 열 제목과 일관된 구분선을 사용합니다. 긴 설명은 표 밖의 문단으로 옮깁니다.
- 코드 블록에 `powershell`, `sh`, `json` 등 언어를 표시합니다. 사용자 입력과 실행 결과를 구분합니다.
- 상대 링크는 대소문자를 포함해 실제 경로·앵커를 검증합니다. 외부 403/429는 링크 파손으로 단정하지 않습니다.
- Mermaid 도식은 설명을 보조하며, 실행·승인되지 않은 흐름을 완료 상태처럼 그리지 않습니다.
- 전문적인 기술 문체를 사용하고 독자의 전문성을 낮춰 가정하는 표현을 피합니다.

## 신뢰·공개 경계

- 새 R01 추론과 과거 W4 앵커를 별개 사례로 표기합니다. AI 정확성과 블록체인 기록 무결성을 구분합니다.
- LIVE, SYNTHETIC, RECORDED, LOCAL_HARDHAT와 각 실행 환경을 구분합니다.
- 비공개 이메일·원문·salt·키·DB·개인 경로·모델 가중치를 공개 문서에 복사하지 않습니다.
- W4 공개 evidence 원본, canonical JSON, hash, Merkle·ABI·TrustProfile, 실행 로그와 승인 ID를 형식 정리 명목으로 바꾸지 않습니다.
- S1 승인, LOCK, TEST, 새 Epoch·거래는 별도 승인·실제 증거 없이 완료로 표시하지 않습니다.

## 제출 전 점검

변경 파일과 `git diff --check`를 확인하고, 상대 링크·앵커·기밀정보 패턴·W4 tree를 검사합니다. 검사하지 않은 외부 URL·PDF·실행은 `NOT_VERIFIED`로 남깁니다. 문서 전용 브랜치와 PR에서 CI 및 독립 리뷰를 거치며, main 병합은 별도 승인에 따릅니다.
