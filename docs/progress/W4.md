## CHAIN-07 and CHAIN-13 — frozen epoch sender

`backend/contracts/scripts/register-epoch.ts` accepts only F's atomically frozen positive uint64 epoch ID, nonzero root, positive uint32 count, and uint16 protocol version. It has these non-negotiable boundaries:

1. Read `epochs(epochId)` first. Equal root/count/version is confirmed without retransmission; a different registered value stops as `ROOT_CONFLICT` with no send.
2. Serialize signed raw transaction, tx hash, nonce, and `SUBMITTING` state to a restricted local journal before broadcast. F's SQLite must durably store the same submission boundary before calling the sender.
3. Broadcast the same raw transaction, persist `SUBMITTED`, then require `receipt.status=1`, trusted `to`, complete `EpochRegistered` arguments, and `epochs(epochId)` equality before `CONFIRMED`.

Hardhat crash-injection coverage is in `backend/contracts/test/EpochRecovery.ts`: (1) a crash after successful broadcast but before DB advance reconciles from the getter with no resend; (2) a crash after durable signing but before broadcast sends the exact saved raw transaction once; (3) a nonzero different root stops with no overwrite or send.

No actual epoch was submitted yet because F's actual-model receipt freeze values were not present in this checkout. A synthetic W3 root will not be substituted.

## CHAIN-12 — approved profile reader

`frontend/src/domain/approvedProfiles.ts` restricts selection to `BASE_SEPOLIA_DEMO` and `LOCAL_HARDHAT_FALLBACK`. `RpcLedgerReader` independently calls RPC for `eth_chainId`, immutable `publisher()`, transaction receipt, event, `epochs(epochId)`, and head block. It treats another chain/contract/publisher/event/getter mismatch as `UNTRUSTED_ANCHOR`; transport errors remain `RPC_UNAVAILABLE`/pending.

For a standalone browser validation, open `/verify?profile=BASE_SEPOLIA_DEMO&rpc=<public-RPC-URL>` and paste the actual bundle. The URL selects only a built-in profile; it cannot supply profile fields. The default demo path remains the clearly labeled local simulation.

The reader requires the bundle tx/block fields to match the actual receipt, but never treats them as the trust root. Confirmation policy is profile-specific: Base remains at 12 confirmations pending any separately approved change; local uses 1.
