## 2026-10-18 실제 T → A status 왕복

T 노트북에서 사설 네트워크(Tailscale)를 거쳐 A의 Windows OpenSSH에 접속하고, 비관리자 F 전용 계정의
고정 status wrapper로 원본 F SQLite의 Epoch 상태를 받았습니다. 체인 서명·송신은 하지 않았습니다.

| 시험 | T 결과 | A 서버 기록 |
| --- | --- | --- |
| A 호스트키 지문 대조 | 일치 | — |
| 정상 status (원격 명령 없음) | 9개 필드 JSON, `FROZEN`, `tx_hash=null`, exit 0 | 공개키 인증 후 고정 강제 명령만 실행 |
| 비승인 원격 명령 | `REMOTE_COMMAND_DENIED`, exit 126 | 요청 명령 대신 고정 강제 명령 실행 후 거부 |
| PTY 요청 | `PTY allocation request failed`, 셸 없음 | 강제 명령 세션만 생성 |
| 원격 포트 포워딩 | `remote port forwarding failed`, exit 255 | 세션 없이 종료 |
| SFTP | `subsystem request failed`, exit 255 | subsystem 없음으로 거부 |
| 다른 계정 | `Permission denied (publickey)`, exit 255 | invalid user로 인증 전 차단 |

- 접근 범위: 사설망 정책은 T 장치 → A 장치 TCP 22 하나만 허용합니다. Windows 방화벽도 T 주소만 허용하고
  다른 IPv4 SSH는 차단합니다. sshd는 A 사설 IPv4 하나에서만 listen하고 공개키 인증만 받습니다.
- DB 불변: 시험 전후 조회 전용 스냅샷의 파일 identity, 바이트 SHA-256, 스키마, Epoch 행, member, 행 수가 모두 같습니다.
- 시험 후 sshd를 다시 Stopped/Disabled로, F 전용 계정과 신규 방화벽 규칙을 Disabled로 돌려놓았습니다.
- 이 status JSON은 송신 전 durable ACK(prepare)가 아닙니다. status 성공만으로 송신 준비 완료로 보지 않습니다.

## 정책 승인과 신뢰 경계

정책은 `W4_PROVISIONAL_E2E_ONLY`, `team_approved=false`입니다. 정식 선택 규칙은
FRR≤X, HRR_TOTAL≤B를 만족하는 후보 중 HAR 최소, 동률이면 RP 최대→HRR_TOTAL 최소입니다.
X/B가 승인되지 않아 운영 정책을 채택하거나 LOCK하지 않았습니다. `none`은 정상 클래스의
운영 proxy로만 사용하며 플랫폼에서의 정상 판정/ALLOW와 동일하지 않습니다.

실제 Epoch의 공개 proof/anchor는 null입니다. 모델의 실제 실행과 정확성을 blockchain이
증명한다고 주장하지 않습니다. T의 공개 JSON 독립 검증 PASS는 팀 보고입니다.
