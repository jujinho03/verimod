## 남은 승인·입력 — 종합 결정 메모

### 1. X/B와 정책 후보

비교 근거 전체는 [AI-11 결정표](../eval/threshold-rationale.md)를 따른다. 아래 값은 모두 미승인 관측 경계이며 새 기본값이 아니다.

| 비교안 | X / B 가정 | FRR / HAR | 검토/1,000건 | 결정상 위험 |
|---|---|---|---:|---|
| H50-90_O50-90 | 32/547 / 542/1255 | 5.85% / 12.71% | 431.87 | 낮은 FRR와 기존 HAR를 유지하려면 높은 검토량 수용 근거 필요 |
| H50-75_O50-90 | 53/547 / 354/1255 | 9.69% / 12.71% | 282.07 | HAR 유지·중간 검토량. 위 후보 대비 정상 proxy 제한21건 증가·검토188건 감소 |
| H75-90_O75-90 | 32/547 / 344/1255 | 5.85% / 28.67% | 274.10 | 검토량 감소 대신 유해 proxy 자동 허용 증가 |
| H50-75_O75-90 | 53/547 / 229/1255 | 9.69% / 22.32% | 182.47 | 낮은 검토량과 더 높은 오류 사이의 절충 |

FRR 우선이고 실제 검토 여력이 있다면 첫 안을 우선 검토하는 것이 근거에 맞다. 여력 근거 없이 X/B를 승인하거나, 낮은 검토량만 보고 HAR 증가를 묵인하지 않는다. 현 후보 풀에서 X<32/547이면 INFEASIBLE이며, 다른 규칙·후보 풀·운영 상한의 재협의는 별도 정책 결정이다.

승인 시 수행 범위: 승인자·시각·정확한 X/B·채택/기각 사유 기록, 기존 원행 검증 결과와의 결합 확인, 전체25개 공식 feasible/infeasible 판정, A/F 합의에 따른 최종 정책 패키지 검토 준비. **Manifest 확정·F 소유 코드 변경·실제 LOCK·TEST 실행은 그 승인에 자동 포함되지 않는다.**

### 2. 정확한 Validation 행 근거 — 해결 완료

사용자가 명시한 predictions와 Validation split의 실제 해시가 각각 W4 기대값과 일치했다. 두 파일만 직접 읽고 1,255행 전체 대응·25후보 재계산·실제 비식별10건 분석을 완료했다. 공개 case ID와 원행 번호의 대응은 새 Git 제외 경로에 원문 없이 저장했고 공개 결과에는 원문·뉴스 제목·record ID·행 번호·텍스트 해시를 남기지 않았다. 의미·라벨 재판정과 공개 원문 권한은 별도 미확인이다.

### 3. Model/Policy LOCK과 최초 TEST

정책·모델·전처리·보정 여부·Manifest/hash·평가 코드/환경·그룹 가정·latency 프로토콜·parity/실패 회귀를 준비하고 별도 LOCK 승인을 받아야 한다. 실제 LOCK commit SHA/시각 검증 후에만 별도의 최초 TEST 실행 승인을 받는다. 준비 버전의 실제 데이터 로더와 영속적 1회 실행 claim은 미구현이므로, 승인 전 데이터 접근 없이 검토할 실제 실행 연결 작업도 남아 있다. 현재 날짜 도달이나 일반 진행 지시를 개봉 승인으로 해석하지 않는다.

### 4. DOC-09·T/F·전달

1·2회차 원문이 도착하면 팀 요약과 대조한다. T/F에는 코드 SHA·회귀·실제 실행 증거를 요청할 인계표를 준비했으며 메시지를 대신 전송하지 않았다. 원격 push/merge와 팀 전체 GATE-5 최종 승인도 별도다.

## GATE-5 위험과 다음 순서

G5-01·G5-02는 승인과 LOCK/TEST 순서 때문에 BLOCKED다. G5-03은 A의 보존 대조를 완료했지만 T/F의 W5 재사용 범위 확인은 별도다. G5-04~06의 Lifecycle·Private Package·실제 RPC/Manifest UX는 담당자 증거를 검증하기 전 PASS로 표시하지 않는다. G5-07은 A 원행 후속128개, 승인 준비 관련61개, 실행 guard 포함166개 검사·문서 근거를 확보했으나 신규 main CI 및 팀 통합 증거는 남아 있다. 세 검사 수는 중복되며 합산하지 않는다.

Critical path: **X/B·정책 결정 → A/F 계약 합의·F 담당자 지원 → 새 정책 검증/Manifest 확정 → 별도 실제 LOCK → LOCK SHA에 묶인 최초 TEST 승인·1회 실행 → 팀 GATE-5 판정**. Validation 원행 확인은 해결했다. 독립 문서·합성 준비 작업은 승인 대기 때문에 중단하지 않고 완료했다.

GATE-5 미통과 상태에서는 SHOULD=0·신규 기능=0을 유지하고 미완 MUST부터 처리한다. AI-22 외부평가·재학습·기능 확대를 착수하지 않는다. 범위 축소·이월은 팀장 결정 사항이며 TEST 조기 개봉으로 마감 문제를 해결하지 않는다.
