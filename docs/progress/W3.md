W2가 팀 전체 semantic freeze였다고 가정하지 않는다. 보존된 W2 evidence는 Node vector 20/20, Chromium vector 20/20, Python canonical golden 6/6, Python ReceiptBody golden 5/5, ordered Merkle 및 `issuer_seq` validation이다. 이는 신규 W3 성과가 아니며 계속 통과해야 하는 regression baseline이다.

## CHAIN-04 / 05 구현 경계

`backend/contracts/contracts/VeriModAnchor.sol`은 ABI draft와 동일한 최소 상태만 저장한다.

| 항목 | 계약 동작 | 계약이 주장하지 않는 것 |
|---|---|---|
| `epochId` | `uint64`; backend가 1부터 단조 증가시키는 운영 방향 | global continuity, 누락 불가능성 |
| epoch | root/count/protocolVersion을 1회 등록 | global append-only log/head registry |
| publisher | immutable publisher만 등록 가능 | multisig, DAO, upgrade 권한 |
| protocolVersion | 임의 `uint16`을 저장 | 지원 여부 판정 (verifier/TrustProfile 책임) |

저장하거나 추가하지 않는 범위: timestamp, model hash, raw receipt/text/PII, token/reward, DAO, multisig, upgrade proxy, global head registry, global append-only enforcement, actual model execution proof.

Hardhat regression은 다음 7개를 검증한다: 정상 register/getter, duplicate, unauthorized publisher, `count=0`, zero root, `EpochRegistered` arguments, arbitrary protocolVersion 저장. CI contracts matrix는 Hardhat 3가 요구하는 Node 24에서 `npm test`와 `npm run build`를 실행한다. W2의 “Node 20/20”은 Node.js version이 아니라 Node-side regression case 수다.

## TrustProfile W3 freeze candidate boundary

schema/field meaning은 `docs/spec/trust-profile.md`의 다음 기준을 사용한다: `chain_id=84532` 방향, `contract_address` 및 `publisher`는 verifier trust root와 on-chain getter 대조 대상, `protocolVersion`은 verifier가 지원 여부를 판정, `min_confirmations`는 profile policy, RPC URL/locator는 trust root가 아니다. 이것은 W3 freeze **candidate**이며, Entry Closure PASS 전에는 team semantic freeze로 표기하지 않는다.

다음은 deployment 후에만 확정한다: actual contract address, actual publisher, deployment tx/block/explorer evidence, exact `min_confirmations`. Base Sepolia target은 chain ID 84532이며 confirmation 숫자는 2회차 금창섭 멘토링과 testnet 관측 뒤 W4 actual deployment 전에 동결한다.
