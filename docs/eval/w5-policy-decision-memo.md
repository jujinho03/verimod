## 2. 오류비용과 검토 예산의 운영 근거

정상 proxy 제한1건 비용을 cR, 유해 proxy ALLOW1건 비용을 cH, 검토1건 비용을 cV로 두면 비교용 손실은 `none_RESTRICT×cR + harmful_ALLOW×cH + REVIEW×cV`로 쓸 수 있다. 실제 가중치는 미측정이며 공식 선정 목적함수를 이 식으로 교체하지 않는다. A가 B보다 줄이는 정상 제한21건에는 추가 검토188건이 필요하고, B가 D보다 줄이는 유해 ALLOW68건에는 추가 검토125건이 필요하다. 검토의 지연·오판·원문 노출 비용은 별도 운영 평가가 필요하다.

팀이 확인할 B 근거는 일 입력량 V, 검토자 수 n, 근무시간 H, 실제 사용 가능 비율 u, 건당 검토시간 t, 대기열/피크 목표다. 단순 용량 상한은 `K=floor(n×H×60×u/t)`, 비율은 `K/V`로 산정할 수 있으나 어느 값도 이번에 채우지 않았다. 그룹/도메인 이동과 TRUNCATED 유입은 Validation 비율보다 실제 업무량을 늘릴 수 있다. 임의의 B를 승인값으로 설정하지 않는다.

| 운영 Model/Policy Manifest 확정 | **BLOCKED — 미승인** | 최종 threshold·모델/전처리/calibration 경계를 A/F와 확인하고 새 Manifest/hash 및 Python/Node parity·fail-closed 근거 준비 |
| 실제 Model/Policy LOCK | **BLOCKED — 별도 승인 필요** | 준비 자료 검토 후에만 LOCK 파일/commit 생성, SHA·시각 검증. 일반 코드 커밋과 구분 |
| 최초 TEST 접근·평가 | **BLOCKED / SEALED** | 실제 LOCK SHA 검증 이후 별도의 명시적 최초 평가 승인 필요. 이번 실행은 승인에 해당하지 않음 |
| 원격 push/merge·팀 GATE-5 | **BLOCKED — 별도 승인/증거 필요** | 원격 전달과 T/F 증거 검증·최종 Gate 판정을 개별 처리 |

권장 다음 결정은 **검토역량 근거를 포함한 X/B와 후보 채택**이다. 정책 선택 이후에도 Manifest 확정·실제 LOCK·TEST 승인을 하나의 일반 진행 승인으로 묶지 않는다. [전체25후보·LOCK 준비](threshold-rationale.md), [W5 진행 기록](../progress/W5.md)을 함께 검토한다. MUST 이전 SHOULD·외부평가·재학습·기능 확대를 시작하지 않는다.

## 4. 팀장이 실제 승인할 항목

정확한 X와 B, 근거가 되는 정상 제한/유해 허용 비용 및 검토역량, 최종 후보와 채택/기각 사유, 현 모델·전처리·UNCALIBRATED·ANY_RESTRICT 유지 범위를 명시해 승인한다. 이것이 새 Manifest 확정·F 소유 코드 변경·실제 LOCK·최초 TEST·push까지 승인한 것은 아니다. B 미확정이면 해당 항목을 미확정으로 유지한다.

## 5. 승인 후 정확한 실행 순서

1. `select_w5_policy.py`의 준비 전용 formal 거부를 승인 기록에 결합한 별도 공식 선정 경로로 보완한다. 승인값으로 전체25개 feasible/순위·동률을 기록하며 후보·threshold를 임의 추가하지 않는다.
2. A/F 합의 및 담당자 승인 후 새 A 생성기 `ai/scripts/prepare_w5_policy_release.py`(제안)를 작성한다. 새 `ai/artifacts/manifests/w5_policy/<approved-policy-id>/<unique-run-id>/`에만 승인 패키지를 준비하고 별도 Manifest 확정 승인을 받는다. 기존 W4 생성기는 실행하지 않는다.
3. F는 자기 검증·서버 로딩·발급 연계의 명시적 승인 정책 지원을 구현한다. A는 별도 `ai/scripts/w5_policy_parity.mts`(제안)로 고정 F SHA·T canonical/hash와 새 Manifest를 대조한다. 21개 이상 경계/action/reason/rule/hash parity와 fail-closed 회귀를 새 증거 경로에 기록한다. 현재 생성한84개 준비 벡터를 Node PASS로 승계하지 않는다.
4. Model/Policy·threshold·code/env·승인·그룹/독립성·latency·bootstrap·실제 평가기의1회 실행 guard를 LOCK 후보 자료에 결합한다. 별도 LOCK 승인을 받은 뒤에만 LOCK 파일/commit 생성·SHA/시각 검증을 수행한다.
5. 검증된 LOCK SHA를 명시한 별도 최초 TEST 평가 승인을 받은 뒤 승인된 평가기를1회 실행한다. 현재 TEST는 SEALED이며, 일반적인 다음 단계·문서 승인·날짜 도달은 최초 평가 승인이 아니다. 원격 push/merge·팀 GATE-5 승인도 따로 처리한다.
