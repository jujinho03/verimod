## 요청과 응답

`POST /infer`, `Content-Type: application/json`:

```json
{
  "text": "오늘은 날씨가 좋아서 친구와 함께 산책했어요.",
  "content_commitment": "0xabababababababababababababababababababababababababababababababab",
  "request_id": "korean_short"
}
```

C01이 요청 스키마를 동결하지 않았으므로, 요청 형태는 AI-09의 로컬 전송 선택입니다.
`text`와 소문자 hex32 `content_commitment`는 필수입니다. `request_id`는 선택이며(없으면 UUID v4),
1–128자의 ASCII ID 문자입니다. 추가 key, 문자열이 아닌 text, 짝 없는 Unicode surrogate,
잘못된 JSON은 거부합니다. 비어 있거나 공백뿐인 text는 `EMPTY_INPUT`입니다. 검증 실패에는
생성한 request ID를 쓰고, 유효한 요청은 제공된 request ID를 그대로 씁니다.

추론은 `preprocess_text`, `score_array`, `score_to_ppm`, `validate_i1`을 재사용합니다.
처리 순서는 Unicode codepoint 500개 HEAD 자르기, 그다음 고정 tokenizer의 오른쪽 자르기로
special token 포함 128 token입니다. 둘 중 하나라도 자르면 `TRUNCATED`입니다.
실제 선정 모델 logits로 native softmax 점수 3개를 만듭니다. `hate`와 `offensive`만
`floor(score * 1_000_000 + 0.5)`로 한 번씩 변환해 노출합니다.
합계 보정, 노출된 두 점수의 재정규화, `none`의 ALLOW 변환, 정책/조치 생성은 없습니다.
점수는 UNCALIBRATED이고 evidence는 비어 있으며, 호출자의 원래 commitment를 그대로 반환합니다.

실제로 받은 응답(mock 아님):

```json
{
  "ok": true,
  "request_id": "korean_short",
  "inference": {
    "output_version": "inference/1",
    "inference_id": "9927c26a-fb70-47d8-91bf-2f33c4cc937a",
    "content_commitment": "0xabababababababababababababababababababababababababababababababab",
    "model_manifest_hash": "0x96b337807aa81ebac6acc3997586cbd351cbfa5c9c44028d479cab327ad0b7c1",
    "taxonomy_id": "verimod-ko-beep-hate",
    "taxonomy_version": "1",
    "scores_ppm": {"hate": 3401, "offensive": 10902},
    "score_semantics": "UNCALIBRATED",
    "input_status": "FULL",
    "evidence": [],
    "inferred_at": "2026-10-14T04:35:09.251Z"
  }
}
```

## Fail closed 처리

처리된 `/infer` 실패는 모두
`{"ok":false,"request_id":"...","error":{"code":"...","retryable":false}}` 형태만 씁니다.
오류에는 점수나 inference 객체를 붙이지 않습니다.

| 조건 | HTTP | I1 code | Retryable |
| --- | --- | --- | --- |
| 빈 text/공백뿐인 text | 400 | EMPTY_INPUT | false |
| 잘못된 body/Unicode/commitment | 400 | INVALID_INPUT | false |
| 유한하지 않거나 형태가 틀린 logits, 잘못된 I1 점수 | 503 | INVALID_MODEL_OUTPUT | false |
| 제한 시간 초과 | 504 | INFERENCE_TIMEOUT | true |
| 모델 없음/손상, 로드/forward 실패, 사용 중인 slot | 503 | INFERENCE_UNAVAILABLE | true |

503 unavailable은 D24의 작업 가정을 따릅니다. 나머지 status/retry 매핑은 AI-09의 로컬 선택이며,
**I1 전송 초안이 이제 동결됐다는 주장이 아닙니다**.

`VERIMOD_INFERENCE_TIMEOUT_SECONDS` 기본값은 10이며, 유한한 양수여야 합니다.
`VERIMOD_MODEL_DIR`와 `VERIMOD_HF_CACHE`로 로컬 산출물 위치를 바꿀 수 있지만, SHA와
revision 고정은 그대로 적용됩니다. 요청으로 이 설정을 바꿀 수 없습니다.

event loop는 제한된 executor slot 하나를 기다립니다. 제한 시간 초과/연결 끊김 시 늦은 결과는 버리고
늦은 예외는 소비하며, native forward가 끝날 때까지 slot을 붙잡아 둡니다. 동시 호출은 503으로
fail-closed되며 무제한 대기열은 없습니다. native forward가 영구히 멈추면 프로세스를 재시작해야 합니다.
timeout은 HTTP 대기를 제한할 뿐 native PyTorch 코드의 실행 시간을 제한하지 않습니다. 이는 로컬 CPU
서비스이며, 운영 처리량이나 다른 장치 성능은 주장하지 않습니다.
